# Планировщик отпусков РФ 3.0

Браузерный планировщик с переносимой JSON-базой всех лет. Для работы нужен только `index.html`: без установки, сервера, React и загрузки библиотек. Интернет нужен только для обновления календаря по кнопке.

## Работа на терминальном сервере

1. Скачай `index.html` этой версии и открой в Edge или Chrome.
2. Нажми **«Сохранить как базу…»** и выбери `grafik_otpuskov_all.json` в своей папке «Документы», которая переносится между серверами.
3. После подключения включается автосохранение. Статус **«Сохранено и проверено»** появляется только после записи, закрытия файла и повторного чтения.
4. После перезапуска нажми **«Открыть прежний файл»**, если браузер сохранил доступ. После смены сервера или браузерного профиля нажми **«Открыть базу JSON»** и выбери тот же файл.
5. Периодически сохраняй **«Скачать JSON»** в отдельную папку резервных копий.

Браузер запоминает разрешённый файловый дескриптор в IndexedDB, а не абсолютный путь Windows. Политики организации могут запрещать прямую запись и хранение разрешения. В этом случае используй **«Открыть JSON без подключения»** и **«Скачать JSON»**. Скачивание не означает подтверждённую запись в исходный файл: проверь папку сохранения. При закрытии с неподтверждёнными изменениями браузер предупредит.

В Firefox и других браузерах без File System Access API сохранение выполняется скачиванием. Открывать локальный HTML можно без интернета. Для браузера, ограничивающего API у `file://`, можно открыть размещённый по HTTPS планировщик: данные всё равно остаются в выбранном локальном файле.

## Годы, история и импорт

- Каждый год хранит свой состав сотрудников, должности, норму, порог пересечений, график и праздники.
- При создании нового года копируются состав и настройки текущего года; даты отпусков остаются пустыми. Изменение имени, нормы или удаление сотрудника не меняет другие годы.
- Переходящий отпуск отображается в начале следующего года и учитывается в пересечениях. Нажатие на его полосу открывает исходный год. Дни относятся к графику года начала отпуска.
- **«Открыть базу JSON»** заменяет базу в окне после подтверждения. **«Добавить из JSON»** добавляет годы, сохраняя остальные. При совпадении годов перечисляет их и предлагает заменить целиком. Слияния отдельных сотрудников внутри одного года нет.
- Поддерживаются прежние экспорты v1 (`employees[].parts`), v2 (`schedules`) и v3. Форматы проверяются до изменения текущей базы; UTF-8 BOM допускается.
- Встроена одна предыдущая запись всего файла. **«Вернуть предыдущую запись»** восстанавливает её в окне; после проверки нужно сохранить. Это дополнение к отдельным резервным копиям, а не полная история версий.
- Перед открытием, импортом и откатом создаётся отдельная браузерная копия, доступная в разделе восстановления. Если записать её нельзя, сначала потребуется скачать JSON.
- Старое хранилище `grafik_otpuskov_v2` не перезаписывается. Новая запасная копия использует `grafik_otpuskov_v3`. Если старая копия повреждена, приложение сообщает об этом и позволяет скачать исходный текст.

Один JSON предназначен для последовательной работы одного пользователя. Перед записью проверяется, не изменился ли файл с момента открытия. При конфликте автосохранение останавливается. Нельзя гарантировать блокировку одновременно работающих копий на разных терминальных серверах или сетевой файловой системе: общий многопользовательский доступ не поддерживается.

## Календарь и расчёт

Принцип расчёта сохранён: праздничные дни не расходуют дни отпуска, обычные и перенесённые выходные расходуют. «Конец» означает последний день отпуска, а не первый рабочий день выхода. Проверки нормы и наличия части не короче 14 дней носят вспомогательный характер.

**«Обновить через интернет»** загружает XML выбранного года из [xmlcalendar.ru](https://xmlcalendar.ru/) и при недоступности использует [зеркало xmlcalendar/data](https://github.com/xmlcalendar/data). Это два адреса одного стороннего источника, не два независимых календаря. У основного сайта возможен запрет CORS, тогда используется зеркало. Запросы не содержат сотрудников и график отпусков.

До применения проверяются страна, год, формат, уникальность дат, коды праздников и совпадение праздничного перечня со ст. 112 ТК РФ. Из XML берутся только `t=1`, `h` задан, `f` не задан. Перенесённые выходные и сокращённые дни не включаются. Неполный/неожиданный список, тайм-аут, HTTP-ошибка или неверный XML оставляют прежние даты и дату последнего успешного обновления. Если закон изменит перечень праздников, новая дата потребует проверки и обновления приложения, а не будет принята молча.

Проверочный перечень сверен **04.11.2026** по [Минтруду России](https://mintrud.gov.ru/labour/relationship/351) и [Банку России](https://www.cbr.ru/other/holidays/). Последние доступные XML за 2026 и 2027 годы проверены. Встроенная копия работает офлайн; ручные изменения импортируются без замены и помечаются. Перечень не включает региональные праздники. Для лет вне 2025–2027 выводится предупреждение: они отдельно не сверены, текущий перечень нельзя считать гарантией исторической или будущей редакции закона.

## Интерфейс и выгрузка

Закреплённая колонка сотрудника и заголовки таблицы, масштаб графика, светлая/тёмная тема, печать, Excel без внешних библиотек. Добавление сотрудника переводит фокус в новую строку. Пустой или незавершённый отпуск виден как предупреждение. Окна перегрузки проверяют совпадение должностей в один день, а не только внутри объединённого периода.

Максимум 8 частей на сотрудника, 2000 сотрудников на год, 366 дней в части, JSON до 10 МБ. Большие таблицы могут работать медленнее. Для управленческой работы удобнее широкий экран; таблица на узком экране прокручивается отдельно.

## Разработка и проверки

Исходники: `src/planner.html`, `src/core.js`, `src/storage.js`, `src/calendar.js`, `src/app.js`. Сборка просто встраивает скрипты в один распространяемый `index.html`; сборщик и Node.js пользователю не нужны.

```sh
node scripts/build.mjs
node scripts/check.mjs
node --test tests/core.test.mjs
npm ci
npx playwright install chromium
npm run test:browser
```

CI проверяет, что HTML соответствует исходникам, синтаксис, сетевые обращения, модель данных, файловую запись и сценарии браузера. Браузерные тесты используют настоящие FileSystemFileHandle/потоки Chromium OPFS, подменяя системное окно выбора файла. JSON переносится скачиванием и загрузкой в новый изолированный профиль. Онлайн-ошибки воспроизводятся контролируемыми ответами, отдельно разбираются снимки реальных XML.

На рабочем Windows-сервере отдельно проверь разрешение выбора файла и запись в переносимую папку. Политики твоего домена нельзя воспроизвести в автоматическом тесте.

## Выпуск и откат

Подготовлены версия 3.0.0, [заметки выпуска](docs/RELEASE-3.0.0.md) и CI-артефакт `otpusk-planner-rf-3.0.0`. Публикация на Pages произойдёт только после слияния PR в ветку, настроенную для Pages. Старая публикация и старые Releases не заменяются этой веткой.

Перед переходом сохрани JSON из версии 2. Для отката верни старый HTML и его прежний JSON. Версия 2 не поддерживает новые независимые составы сотрудников v3, поэтому открывать накопленную базу v3 в старом приложении нельзя.
