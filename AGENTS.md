# Планировщик графика отпусков РФ

## Перед правками

- Проверь репозиторий, ветку и рабочее дерево: `git remote -v`, `git branch --show-current`, `git status --short`. Сохраняй чужие изменения.
- Базовая ветка — `main`. Работай в отдельной ветке. Слияние в `main`, публикация GitHub Pages и выпуск EXE требуют отдельного поручения.
- Начни с [README.md](README.md) и текущего кода. При расхождении опиши его в результате и сверяй поведение по коду и проверке в браузере.

## Код и данные

- Браузерная точка входа — `index.html` в корне. Для пользователя сборка не нужна. Редактируй исходники в `src/`, затем выполняй `node scripts/build.mjs`, чтобы встроить их в распространяемый HTML. Сохраняй запуск через `file://` и GitHub Pages.
- Основная база v3 — выбранный пользователем JSON всех лет. `localStorage` — запасная копия, IndexedDB — запомненный файловый дескриптор. Сохраняй совместимость импорта v1/v2/v3 и старый ключ v2. Состав сотрудников, должности, настройки, график и праздники относятся к своему году. Не путай скачивание с подтверждённой записью в файл.
- Онлайн-источник календаря — xmlcalendar.ru и [его зеркало xmlcalendar/data](https://github.com/xmlcalendar/data). При обновлении проверяй страну, год, полноту и федеральный перечень. При ошибке сохраняй текущие даты и время последнего успешного обновления. Различай праздничные дни, обычные выходные и переносы.
- Репозиторий публичный. Используй вымышленные данные в тестах, скриншотах и PR. Рабочие JSON, сведения о сотрудниках и секреты держи вне Git.

## Проверка изменений

- Для правок приложения открой `index.html` в браузере и проверь сценарий из задачи, ошибки в консоли и `git diff --check`.
- Для правок дат проверь отпуск с праздником и переход через границу года. Для правок хранения проверь смену года, перезагрузку и цикл экспорт → импорт. Указывай, что реально проверено.
- Обязательные проверки: `node scripts/check.mjs`, `node --test tests/core.test.mjs`, `npm run test:browser` (после `npm ci` и установки Chromium Playwright). Для файлового доступа проверь отказ, внешний конфликт и изменения во время записи.
